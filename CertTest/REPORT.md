## Findings

1. **Standard axioms suffice, at no cost.** With the paper's argument, all machine work is exact
   rational arithmetic and integer comparisons; the kernel checks the 23 rows in about 20 s.
2. **The paper's enclosure $w_0\in[0.895,0.896]$ (`Auto.DIR.w₀_mem`) is too coarse for (7.3).**
   Used rigorously (lower bound $w_0\ge0.895$, $I(a/w_0)\ge I(a/0.896)$), the minimum of
   $\underline{g_{P,2}}$ drops below $10^{-4}$ (margin $-3.6\cdot10^{-5}$); the paper's code uses
   $w_0$ to full precision. `w₀_mem_fine` ($[0.8957,0.8958]$, proved with the same series bounds)
   fixes this; claims with smaller margins will need even finer enclosures.
3. **LeanCert is not needed and does not help here** (experiments, kept in the history of this
   branch):
   * its `erf` and `sqrt` point enclosures are too loose to be useful; its multivariate tactic does
     not support `log`/`sqrt` (hence `rpow`), so 2-D claims cannot be automated with it anyway;
   * its integral checker does not reach the precision needed for $\Phi$ at the paper's partition
     points even in native mode (23 of 23 failed, 296 s), and in kernel mode a single coarse
     integral bound took 808 s, three took > 53 min and > 13 GB RAM (aborted);
   * for coarse, non-paper certificates (my first attempt: own box bounds checked by LeanCert)
     kernel and native modes were both feasible (117 s vs 102 s) — but that is not the paper's
     argument;
   * LeanCert is not a Lean `module` package; a `module` file cannot import it ("cannot import
     non-`module` LeanCert.Tactic from `module`"). Without LeanCert this conflict disappears
   (`CertTest/Common.lean` still imports `LeanCert.Core.Expr`, only for the definition of `erf`
   used by early experiments; the final proof does not need it).
4. Generic tools reusable for all 🚗 claims: `partition_one` (and a 2-D analogue), the series
   bounds, $\Phi$/$I$/$J$ point enclosures, $\log_2$ bounds via integer powers, $2^{-2\beta_0}$.

## Recommendations

1. **Do not allow extra axioms.** Prove the 🚗 claims with standard axioms only, as all other
   declarations; drop the LeanCert exception from rule 3 of `AGENTS.md` and forbid
   `native_decide`.
2. **Follow the paper for every 🚗 claim:** its tight lower bound, its monotonicity argument, its
   partition from `partitions.py` ([DIR] `anc/partitions.py`, [DIRX] `partitions.py`), one
   generated `row` lemma per box, checked by exact rational arithmetic. Keep the generator script
   and the certificate data in the repository (e.g. `automation/cert/`).
3. **Before Tasks 2–4 start their 🚗 claims, add shared numerical infrastructure** (a Task-1-like
   step, in `_aux` files): the series bounds, $\Phi$, $I$, $J_w$, $J$ enclosures at rational
   points (both directions), a fine enclosure of $w_0$ (and $x_0$, $w_1$ for [DIRX]),
   `partition_one`/`partition_two`, and helpers for $L_\beta$, $Q_\beta$, rpow constants.
4. **Run a second test on a large claim** (e.g. [DIR] (6.5): 11,059 rectangles, margin
   $1.7\cdot10^{-8}$, or [DIRX] (3.3): 5,506 rectangles) to measure kernel time per row with the
   higher precision needed (more series terms, finer $w_0$); split large claims over several files
   so that builds parallelize.
5. **Remove LeanCert** from `lakefile.toml` (or keep it unused) and keep the module system; nothing
   in this approach needs it.
